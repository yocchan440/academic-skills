TOPIC 07

実験・調査

目的のない実験は、ただ「やりたいことをやった」だけ

  • 研究目的から実験設計を導ける
  • 再現に必要な条件・環境・対象を漏れなく書ける
  • アンケート調査のバイアスを避けられる

操作：← → / Space でページ送り　O キーでスライド一覧

実験の目的を先に書くPurpose first

何のために実験を行うのか。目的がない実験は、やりたいことをやっているだけ（非科学）である。

確認すべき 4 点
  1. 何のために実験を行うのか
  2. 必要なことを測る実験になっているか
  3. 従来研究と比較可能か
  4. その測り方は妥当か
序論の目的から逆算する 序論で「短縮 URL でも性能が維持されるかを明らかにする」と書いたなら、 短縮 URL のみの部分集合での評価が必ず必要になる。 全体精度だけを測っても、目的には答えられない。

4.1　実験の目的

　本実験の目的は、3 章で述べた提案手法が、1.3 節で掲げた要件 1（URL 非依存性）および要件 2（軽量性）を満たすかを検証することである。具体的には、次の 3 つの問いに答える。

　RQ1　全検体に対する検知性能は、従来手法と同等以上か。
　RQ2　短縮 URL を含む検体に限定した場合、従来手法との性能差はどの程度か。
　RQ3　1 件あたりの判定時間は 1 秒以内に収まるか。

※ RQ（Research Question）に番号を付けると、5 章で「RQ2 について」と対応づけて書ける。

書くべき条件のチェックリストReproducibility

第三者が同じ実験をやり直せるか。書き漏らしやすい項目を機械的に潰す。

システム系の実験
  • ハードウェア：CPU 型番、メモリ量、GPU、ストレージ
  • ソフトウェア：OS とバージョン、言語処理系、主要ライブラリのバージョン
  • データセット：出典、取得日、件数、ラベルの内訳、前処理
  • パラメータ：学習率、エポック数、乱数シード
  • 試行回数：何回実行し、どう集計したか（平均／中央値）
  • 比較対象：何と比べたか、その実装は誰のものか
  • 評価指標：定義式つきで
人を対象とする調査
  • 対象者：人数、属性（年齢・所属・経験年数）、募集方法
  • 期間：実施した年月日
  • 手続き：何をどの順で依頼したか
  • 質問項目：全文を付録に載せる
  • 尺度：5 件法か 7 件法か、選択肢の文言
  • 倫理的配慮：同意の取得、匿名化、データの取扱い
  • 回収率：配布数と有効回答数

評価指標は定義式つきで

適合率 P = TP/(TP+FP)、再現率 R = TP/(TP+FN)、F 値 = 2PR/(P+R) とする。 ここで TP はフィッシングサイトを正しく検知した件数、FP は正規サイトを誤って検知した件数を表す。

※ 「精度」という語は曖昧。Accuracy なのか Precision なのかを明示する。

データの偏りに注意 正例と負例の比率を書く。不均衡データで Accuracy だけを報告するのは誤りである （99% が正規サイトなら、全部「正規」と答えるだけで Accuracy 99%）。

公正な実験になっているかFairness

自分に有利な条件を無意識に選んでしまうことは、誰にでも起きる。

ありがちな不公正何が問題かどうするか
提案手法だけチューニングした比較対象の性能を不当に低く見せている比較手法も同じ手間でチューニングする。条件を明記する
テストデータで学習した結果が無意味になる（リーク）学習／検証／テストの分割方法を明記する
都合の良い 1 回だけ載せた再現性がない複数回の平均と標準偏差を報告する
比較手法を自分で実装した実装ミスで性能が落ちている可能性著者公開の実装を使う。無理なら再実装した旨と検証方法を書く
データセットが提案手法に有利一般性がない複数のデータセットで評価する
アンケート調査で特に注意すること ・意図的に集団を選んでいないか（同じ研究室の友人だけに配る、など）
・結果を誘導していないか（「便利だと思いませんか？」は誘導質問）
・回答者が実験者に忖度しない状況をつくれているか

アンケートの質問文Survey design

質問文の作り方ひとつで、結果は簡単に歪む。

問題✗ 悪い質問✓ 良い質問
誘導この機能は便利だと思いませんか？この機能の使いやすさを 5 段階で評価してください。
ダブルバーレル操作は簡単で分かりやすかったですか？（別々に聞く）操作は簡単でしたか／表示は分かりやすかったですか
曖昧な語よく利用しますか？過去 1 か月で何回利用しましたか？
専門用語多要素認証を利用していますか？ログイン時にパスワードに加えて、SMS の確認コードやアプリの承認を使っていますか？
選択肢の偏りとても良い／良い／普通／悪いとても良い／良い／普通／悪い／とても悪い（左右対称にする）
実施前に必ず ① 質問文を指導教員に見せる（配布後は修正できない）
② 数名に予備調査（プレテスト）をして、解釈のぶれを確認する
③ 人を対象とする調査は、所属機関の倫理審査の要否を確認する

統計処理の注意Statistics

数値に差があることと、意味のある差があることは違う。

書くべきこと
  • 用いた検定の名前（t 検定、Mann-Whitney の U 検定 など）
  • なぜその検定を選んだか（対応の有無、正規性）
  • 有意水準（α = 0.05 など）
  • p 値と、可能なら効果量
  • 標本サイズ n

記述例：
　両群の開封率の差についてウェルチの t 検定を行った結果、有意水準 5% で有意な差が認められた（t(58) = 3.42, p < 0.01, Cohen's d = 0.89）。

やってはいけないこと
  • p 値が 0.05 を下回るまで検定を繰り返す（p ハッキング）
  • 有意でなかった結果を報告しない
  • 「有意差がない」を「差がない」と書く
    → 正しくは「有意な差は認められなかった」
  • n = 5 で統計的主張をする
  • グラフの縦軸を途中から始めて差を強調する
卒論での現実的な方針 統計に自信がないなら、無理に検定を使わない。 記述統計（平均・標準偏差・分布の図示）を丁寧に示すほうが誠実である。

このトピックのまとめSummary

実験の章は「やったことの記録」ではなく、「目的に答えるための設計」である。

  • 実験の目的を最初に書く。RQ に番号を付ける
  • 序論の目的から逆算して実験を設計する
  • 環境・条件・データを表にまとめる
  • 評価指標は定義式つきで書く
  • 比較の公正さを自己点検する
  • アンケートは誘導・偏りを避ける
  • 検定名・有意水準・p 値・n を明記する
  • 不都合な結果もそのまま報告する
最も重要なこと 実験をやってから目的を考えてはいけない。目的 → 実験設計 → 実施の順である。 もし実験の途中で目的が変わったなら、序論を書き直す。
