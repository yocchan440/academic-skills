TOPIC 02

論文の構成と章立て

IMRAD という型を身体に入れる

  • IMRAD の 4 要素と、卒論の章立ての対応を説明できる
  • 自分の研究に合わせて章構成を設計できる
  • 「はじめに」「考察」「まとめ」の一貫性を検査できる

操作：← → / Space でページ送り　O キーでスライド一覧

IMRAD とはIntroduction / Method / Results and Discussion

科学論文の標準的な文章構成形式。情報系の論文は IMRAD 形式で書く。

IIntroduction ／ 序論
なぜこの研究が必要なのか。何が分かっていないのか。本研究は何を明らかにするのか。
MMethod ／ 手法・材料
何を、どのような手順・条件・環境で行ったのか。第三者が再現できるか。
RResults ／ 結果
何が得られたのか。事実としての観測値・測定値。
DDiscussion ／ 考察
その結果は何を意味するのか。なぜそうなったのか。何が言えて、何は言えないのか。
A は and Results and Discussion の and。ただし A を Analysis（分析）と捉える考え方もある。 卒論では「結果」と「考察」を別の章に分けて書くことが多い。
なぜ型が必要か 学術論文は散文（エッセイ）ではない。読者は頭から順に読まない。 「手法だけ見たい」「数値だけ確認したい」という読み方をする。 決められた型は、読者がその情報へ最短で到達するための共通のインデックスである。

型を破ると、内容がどれだけ優れていても読まれない。まず型に従うこと。

卒業論文の標準的な構成Standard sections

和文の章題と英語の呼称を対応させて覚えておく。国際会議の論文を読むときにも役立つ。

章和文英語
—論文タイトルTitle
—概要、あらまし、内容梗概Abstract
1序論、はじめにIntroduction
2関連研究、従来研究、関連技術Related Works
3提案方式、提案手法Method / Proposal
4実験、調査Experiment
5評価、考察、検討Results and Discussion
6結論、まとめ、おわりにConclusion
—（謝辞）(Acknowledgement)
—参考文献References
—（付録）(Appendix)
章番号をつけないもの 概要・謝辞・参考文献・付録には章番号をつけない。 これらは本論（論証の本体）ではないためである。
体裁の基本
  • 本文は明朝体
  • 章題・節題はゴシック体
  • 強調は太字ゴシック（日本語にイタリックは使わない）

※ 学科・研究室指定のテンプレートがある場合は必ずそちらを優先すること。

構成の 2 パターンWhere to put related works

関連研究を「前」に置くか「後ろ」に置くかで、論文の印象が変わる。

構成例 1：関連研究を前に置く（標準）
  1. 序論
  2. 関連研究・関連技術
  3. 提案方式
  4. 実験
  5. 評価・考察
  6. 結論

向いている研究：先行研究の限界を出発点にする研究。 読者は「何ができていないか」を理解してから提案を読める。卒論ではこちらを推奨。

構成例 2：関連研究を後ろに置く
  1. 序論
  2. 提案方式
  3. 実験
  4. 評価・考察
  5. 関連研究・関連技術
  6. 結論

向いている研究：提案そのものが新規で、既存研究との比較が「位置づけの確認」に近い研究。 国際会議の論文でよく見られる形式。

判断の目安 提案を理解するために先行研究の知識が必要なら例 1。提案を読んでから「ところで既存研究は」と振り返れるなら例 2。 迷ったら例 1 にする。

各章が答えるべき問いThe question each chapter answers

章を書き始める前に、その章が答えるべき問いを 1 つに絞る。

章答えるべき問い書き終えたら確認
概要この論文を読むと何が分かるのか？単独で読んで意味が通るか
1. 序論なぜこの研究が必要で、何を明らかにするのか？研究目的が 1 文で書かれているか
2. 関連研究どこまでできていて、何ができていないのか？自分の研究との差分が書かれているか
3. 提案方式何を、どうやって、なぜそれで解決できるのか？第三者が再実装できるか
4. 実験目的を確かめるために何をどう測ったのか？条件・環境・対象が明記されているか
5. 評価・考察結果は何を意味し、従来法と比べてどうなのか？できないことも書いてあるか
6. 結論何の問題を、どう解決し、何が良くなったのか？新しい話題を持ち出していないか
この表の使い方 章を書き終えるたびに、右列の項目を自分で点検する。1 章ずつ完成させてから次へ進むと、後戻りが減る。

章・節・項の番号Numbering

階層は原則 3 段まで。深くなりすぎたら、構成そのものを見直す合図である。

1.　序論

2.　関連研究

2.1　フィッシングサイト検知の分類

2.2　URL 特徴量を用いる手法

2.2.1　語彙的特徴量

2.2.2　ホスト情報に基づく特徴量

2.3　本研究の位置づけ

3.　提案手法

　　…

謝辞　（章番号なし）

参考文献　（章番号なし）

  • 章題・節題はゴシック体、本文は明朝体
  • 節が 1 つしかないなら、節に分ける必要はない
    （2.1 があるなら 2.2 が必ずある）
  • 4 段以上（2.2.1.1）は使わない
  • 参考文献に章番号はつけない
  • 節題は体言止めで揃える
    ✗「URL 特徴量を使う」→ ✓「URL 特徴量を用いる手法」
LaTeX なら自動 \section{} \subsection{} \subsubsection{} を使えば番号は自動で振られる。 手で「2.2.1」と打ち込むのは、章を入れ替えた瞬間に破綻するのでやめる。

分量の目安How long?

あくまで目安。ただし極端に短い章は、内容が足りていないサインである。

A4・20 ページの卒業論文の場合
章目安ありがちな失敗
概要1 ページ半分しか埋まっていない
1. 序論2〜3 ページ背景ばかりで目的がない
2. 関連研究3〜4 ページ研究紹介の羅列で終わる
3. 提案方式4〜6 ページ図だけで説明がない
4. 実験2〜3 ページ条件が書かれていない
5. 評価・考察3〜5 ページ結果の羅列で考察がない
6. 結論1 ページ新しい主張を始めてしまう
参考文献15 件以上Web ページばかり
概要に余白は認められない 卒論の概要は1 ページ分をきっちり埋める。余白が残るのは、論じ尽くしていない証拠である。
ページ数を埋めるためにやってはいけないこと
  • 図を無意味に大きくする
  • 行間・余白を広げる
  • 同じ内容を章をまたいで繰り返す
  • ソースコードを全文貼り付ける
    （必要なら付録へ）

最重要：3 点セットの一貫性Consistency

「はじめに」で掲げた目的と、「考察」「まとめ」がずれている卒論は非常に多い。

典型的なずれ
序論
本研究では、短縮 URL を含むフィッシングサイトを高精度に検知する手法を明らかにする。
実験・考察
一般的なフィッシング URL データセットで精度を測定し、特徴量の寄与を分析した。
→ 短縮 URL の検証がどこにもない
まとめ
本研究では、機械学習を用いた検知システムを実装し、その有用性を示した。
→ 目的が「実装」にすり替わっている
正しい関係 序論で掲げた目的を検証するために実験・調査をし、考察し、まとめる。 目的外のことはやらない。やったなら、序論の目的を書き直す。
検査のしかた 序論の「本研究では〜を明らかにする」の 1 文と、まとめの 1 文目を並べて音読する。 同じことを言っていなければ、どちらかが間違っている。

書く順番のおすすめWriting order

論文の並び順と、書く順番は違ってよい。むしろ違うほうが効率がよい。

  1. アウトライン（章・節の見出しだけ）
    ここで指導教員に一度見せる
  2. 3 章 提案方式
    自分が一番よく分かっているところから
  3. 4 章 実験
    やったことをそのまま書けばよい
  4. 5 章 評価・考察
    図表を先に作り、それを説明する形で書く
  5. 2 章 関連研究
    提案が固まってから書くと、差分を書きやすい
  1. 1 章 序論
    全部書けてから書くと、話がぶれない
  2. 6 章 結論
    序論と対応させて書く
  3. 概要
    最後に書く。全体のエッセンスだから
  4. タイトルの確定
    内容が確定してから見直す
  5. 通し読み・推敲
    印刷して赤ペンで。声に出して読む
最初にやるべき唯一のこと 白紙から書き始めない。まず章・節の見出しだけを全部書く。 見出しが書けないということは、その部分の内容がまだ無いということである。

アウトラインの実例Outline example

研究テーマ例：短縮 URL に頑健なフィッシングサイト検知手法

1. 序論

　1.1 フィッシング被害の現状
　1.2 既存検知手法の課題
　1.3 本研究の目的と貢献
　1.4 本論文の構成

2. 関連研究

　2.1 フィッシング検知手法の分類
　2.2 URL 特徴量に基づく手法
　2.3 コンテンツに基づく手法
　2.4 本研究の位置づけ

3. 提案手法

　3.1 設計方針
　3.2 システム構成
　3.3 HTML 構造特徴量の抽出
　3.4 分類器の構成

4. 評価実験

　4.1 実験の目的
　4.2 データセット
　4.3 実験環境と条件
　4.4 比較対象と評価指標

5. 結果と考察

　5.1 検知精度の比較
　5.2 短縮 URL に対する頑健性
　5.3 特徴量の寄与分析
　5.4 提案手法の限界

6. 結論

謝辞

参考文献

注目 1.3 の目的（短縮 URL への頑健性）が、5.2 でちゃんと検証されている。 この対応があるかどうかが、アウトライン段階での最大のチェックポイントである。

このトピックのまとめSummary

構成が決まれば、卒論の半分は終わったようなものである。

  • 情報系の論文は IMRAD（序論・手法・結果・考察）で書く
  • 関連研究は前（標準）か後ろか。迷ったら前
  • 概要・謝辞・参考文献・付録に章番号はつけない
  • 本文は明朝体、章題はゴシック体
  • 各章が答えるべき問いを 1 つに絞る
  • 序論の目的 ↔ 実験 ↔ 考察 ↔ まとめが一直線に繋がっているか、常に検査する
  • 書く順番は「提案 → 実験 → 考察 → 関連研究 → 序論 → 結論 → 概要」
今日のうちにやること 白紙の文書に、章と節の見出しだけを書き出してみる。書けない見出しが、これから埋めるべき研究の穴である。
