関連研究・従来方式

研究紹介の羅列から、研究の「位置づけ」へ

  • 関連研究を分類・整理して提示できる
  • 自分の研究との差分を明示できる
  • 客観的な視点で先行研究を記述できる

操作：← → / Space でページ送り　O キーでスライド一覧

この章の目的Related Works

関連研究の章は、自分の研究の位置づけを明確にするために書く。

各研究について書くこと
  • 何をしているか？ 何ができるか？ 成果は？
  • 方式は？ 適用範囲は？ 前提条件は？
  • できていないことは何か？
章全体で書くこと
  • この分野における自分の研究の位置づけ
  • 関連研究と自分の研究の違い（差分）
  • 自分の研究では何をやって、何はやらないか
最大の失敗：研究紹介の羅列

　田中らは〜を提案している [1]。佐藤らは〜を提案している [2]。鈴木らは〜を提案している [3]。…

これは目録であって関連研究ではない。読者は「それで、あなたの研究はどこにあるの？」と思う。

問うべきこと その研究と自分の研究はどういう関係なのか。何が同じで、何が違うのか。差分はどこか。 自分の研究の価値はどこにあるのか。

客観的に書くBe objective

主観的な視点から従来研究を判断しない。論文から読み取れる客観的な事実だけを書く。

主観的な断定

田中らの手法は精度が低く、実用的ではない [1]。

この研究は古いため、現在では意味がない [2]。

佐藤らの評価は不十分である [3]。

客観的な記述

田中らの手法は、実験に用いた 3,000 件のデータセットに対して F 値 0.78 を達成している [1]。ただし評価は英語サイトに限定されており、日本語サイトに対する性能は報告されていない。

佐藤らは単一のデータセットで評価しており [3]、他のデータセットへの汎化性能は検証されていない。

言い換えの型 ✗「不十分である」→ ✓「〜については報告されていない」／「〜は検証されていない」
✗「精度が低い」→ ✓「〜のデータセットにおいて F 値 0.78 であった」（数値で示し、判断は読者に委ねる）
✗「問題がある」→ ✓「〜を前提としているため、〜の場合には適用できない」
読んでいない論文を引用しない 他の論文の引用文献リストからコピーしただけの引用は、内容が違っていることが多い。必ず原典に当たる。

関連研究の整理の仕方Organize, don't list

研究を分類の軸で整理する。軸が決まれば、自分の研究の置き場所も決まる。

よく使われる分類の軸
  • アプローチ別：ルールベース／機械学習／深層学習
  • 入力データ別：URL のみ／HTML／画像／通信ログ
  • 適用場面別：クライアント側／サーバ側／ネットワーク境界
  • 時系列：初期の研究 → 発展 → 現在の主流
  • 前提条件別：教師あり／半教師あり／ゼロデイ対応

軸は 2 つまで。3 つ以上の軸で切ると読者が迷子になる。

節の構成例

2.1　フィッシングサイト検知手法の分類
　→ 分類の軸をここで提示する
2.2　URL 特徴量に基づく手法
2.3　コンテンツに基づく手法
2.4　視覚的類似性に基づく手法
2.5　本研究の位置づけ
　→ 比較表＋差分の明示。この節が最重要

2.1 に必ず 1 段落 いきなり個別の研究を並べず、まず全体像（この分野にはこういう種類の研究がある）を示す。

比較表で位置づけを示すComparison table

言葉で説明するより、1 つの表のほうが速い。最終行が自分の研究になる。

比較表の作り方 ・列＝評価の軸。自分の研究が優位に立つ軸を必ず 1 つ含める（ここでは「短縮 URL 対応」）
・自分が劣る軸も隠さない（提案手法の F 値は [4] より低い）。隠すと信頼を失う
・○△× を使う場合は、その基準を本文で定義する（「○は〜を満たすことを示す」）
・表は本文で必ず説明する。「表 1 に示す」だけで終わらせない

「本研究の位置づけ」節の書き方Positioning

関連研究の章は、この節に向かって書く。ここで差分を言い切る。

2.5　本研究の位置づけ

　表 1 に示したとおり、フィッシングサイト検知の研究は、入力として用いる情報の種類によって大きく 3 つに分けられる。URL 文字列のみを用いる手法 [3][4] は、ページを取得する必要がないため高速に判定できる一方、攻撃者が URL を短縮した場合に判別性能が低下する。視覚的類似性を用いる手法 [7] は URL に依存しないが、スクリーンショットの撮影と画像処理に要する時間が大きく、大量の URL を逐次判定する用途には適さない。

　本研究は、この両者の中間に位置づけられる。すなわち、ページの HTML を取得する点では [7] と同様に URL 文字列への依存を断ち切りつつ、画像処理を伴わない軽量な構造特徴量を用いることで、[3][4] に近い処理速度を維持することを狙う。

　また、短縮 URL を含む検体に限定した性能評価は、著者の知る限り報告されていない。本研究では、この条件下での評価を行う点においても既存研究と異なる。

使える言い回し 本研究は〜の点で [n] と共通するが、〜の点で異なる。／ 著者の知る限り、〜を対象とした研究は報告されていない。／ 本研究では〜は扱わない。これは〜のためである。
