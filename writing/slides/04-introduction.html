TOPIC 04

序論（はじめに）

論文のストーリーを設計する

  • 序論の 4 ブロック構造にしたがって書ける
  • 「現状 → 課題 → 本研究 → 貢献」の落差をつくれる
  • 研究目的を 1 文で言い切れる

操作：← → / Space でページ送り　O キーでスライド一覧

序論の役割Introduction

序論には論文のストーリーを書く。読者を「なるほど、それは確かに必要な研究だ」と納得させる場所である。

序論が答える 3 つの問い
  1. なぜこの研究が必要なのか？（現状）
  2. 何ができていないのか？（課題）
  3. 本研究は何をどう解決するのか？（目的）
審査員が最初に見る場所 卒論審査では、多くの場合概要と序論だけで研究の価値がほぼ判断される。 序論が弱いと、どれだけ実装を頑張っても評価されない。
序論に書かないもの
  • 実験の詳しい結果（5 章の仕事）
  • 使用技術の教科書的な解説（2 章の仕事）
  • 「私はこのテーマに興味を持った」という動機
    個人的な興味は研究の必要性ではない
  • 研究室の事情（「先輩の研究を引き継いだ」）

必要性は、社会や技術の側にある。あなたの内側にあるものではない。

序論の 4 ブロック構造Four blocks

この順番で書けば、序論は必ず形になる。1 ブロック＝1〜2 段落。

A現状 ／ 背景・社会的要求
この分野で今、何が起きているのか。なぜこの研究が必要なのか。数値・出典つきで書く。
B問題点 ／ 課題
従来研究はどこまでできて、何ができていないのか。存在する問題点・課題を挙げる。
C本研究 ／ 目的とアプローチ
挙げた課題のどれを解決するのか。どういう方法でやるのか。何が新しいのか。 なぜ今までできなかったのか。
D貢献と論文構成
それによって何がどう良くなるのか（効果・性能・貢献）。最後に本論文の構成を 1 段落で示す。
A → B の落差がすべて 「重要である（A）。しかし、できていない（B）」— この落差が大きいほど、C の目的に説得力が出る。 A と B が繋がっていない序論は、読者に「で、何の話？」と思わせる。

A：現状・背景を書くBackground

「近年、〜が注目されている」で始めない。何がどれだけ起きているかを数値で示す。

中身がない

近年、インターネットの普及に伴い、フィッシング詐欺が注目されている。これは大きな社会問題であり、対策が求められている。

「注目されている」「求められている」— 誰が？ どれだけ？ 出典もない。

事実で示している

フィッシング対策協議会への報告件数は、2021 年の約 52 万件から 2024 年には約 172 万件へと 3.3 倍に増加した [1]。警察庁の統計では、2024 年のインターネットバンキングに係る不正送金被害額は 87 億円に達している [2]。フィッシングサイトの自動検知は、この被害を抑制するための第一線の防御手段として位置づけられている。

背景の書き方の型 ① 事実（数値・出典）→ ② その意味（だから何が問題なのか）→ ③ 技術的な位置づけ（どんな対策が取られているか）
背景を書きすぎない 背景は序論全体の 3 割程度。インターネットの歴史から書き始める必要はない。 「この論文を理解するために最低限必要な前提」だけを書く。

B：問題点・課題を書くGap

序論でいちばん難しく、いちばん重要な部分。「しかし」から始まる段落である。

課題の書き方
  1. 従来研究はどこまでできているかを認める
  2. その限界・前提条件を指摘する
  3. その限界がなぜ問題なのかを述べる
先行研究を貶さない 「従来手法は精度が低く不十分である」のような主観的な断定は避ける。 限界には必ず理由がある。その理由（前提条件・想定環境）を客観的に述べる。
課題の記述例

　フィッシングサイトの自動検知については、URL 文字列の語彙的特徴量を用いる手法が広く研究されており、公開データセットに対して 95% を超える精度が報告されている [3][4]。これらの手法は、攻撃者が作成するドメイン名に特徴的な文字列パターンが現れることを前提としている。

　しかし、攻撃者が URL 短縮サービスを利用した場合、この前提は成立しない。短縮 URL では攻撃者が制御できる文字列が失われるため、語彙的特徴量からは正規サイトとの差異が得られないからである。実際に短縮 URL を悪用したフィッシングの割合は増加傾向にあるが [5]、この条件下での検知性能を定量的に評価した研究は見当たらない。

C：本研究の目的を書くObjective

目的は必ず 1 文で言い切る。この 1 文が、論文全体の憲法になる。

目的文のテンプレート

本研究の目的は、〔何を〕を〔どうする〕ことにより、〔何〕を明らかにすることである。

本研究では、機械学習を用いたフィッシングサイト検知システムの開発を目的とする。

「開発」は作業であって研究目的ではない。何を明らかにするのかが不明。

本研究の目的は、URL 文字列に依存しない HTML 構造特徴量を導入することにより、短縮 URL を含むフィッシングサイトに対しても安定した検知性能が得られるかを明らかにすることである。

「なぜ今までできなかったのか」を書く これを書けると、研究の価値が一気に伝わる。
例：従来は HTML の取得に伴う遅延が実用上の障壁であったが、ヘッドレスブラウザの高速化により、この制約は解消されつつある。

D：貢献と論文構成Contributions & Organization

序論の最後は、貢献の箇条書きと構成の案内で締める。

貢献（Contributions）の書き方

本論文の貢献は以下の 3 点である。

  • URL 文字列に依存しない 27 次元の HTML 構造特徴量を設計した。
  • 短縮 URL を含む検体 1,830 件を対象に、従来手法との比較評価を行い、F 値が 0.71 から 0.93 へ向上することを示した。
  • 特徴量の寄与分析により、外部リソースのドメイン分散度が判別に最も寄与することを明らかにした。

※ 貢献は動詞で終える（設計した／示した／明らかにした）。「〜を行った」だけでは貢献ではない。

論文構成（Organization）の書き方

　本論文の構成は以下の通りである。2 章ではフィッシングサイト検知に関する関連研究を整理し、本研究の位置づけを述べる。3 章では提案手法の設計と実装について述べる。4 章では評価実験の設計を示し、5 章でその結果と考察を述べる。6 章で本論文をまとめる。

注意 この段落は序論の最後だけに書く。概要には書かない。 また、章構成を変更したら必ずここも直す（直し忘れが非常に多い）。

序論の完成例Full example

A → B → C → D が 1 本の線で繋がっているかを見る。

A 現状・背景 B 問題点・課題 C 本研究の目的 D 貢献・構成

Aフィッシング対策協議会への報告件数は、2021 年の約 52 万件から 2024 年には約 172 万件へと 3.3 倍に増加した [1]。利用者が偽サイトに認証情報を入力する前に警告を出すためには、フィッシングサイトを自動的に検知する技術が不可欠である。

Bフィッシングサイトの自動検知については、URL 文字列の語彙的特徴量を用いる手法が広く研究されており、公開データセットに対して 95% を超える精度が報告されている [3][4]。これらの手法は、攻撃者が作成するドメイン名に特徴的な文字列パターンが現れることを前提としている。しかし、攻撃者が URL 短縮サービスを利用した場合、この前提は成立しない。短縮 URL では攻撃者が制御できる文字列が失われるためである。短縮 URL を悪用したフィッシングの割合は増加傾向にあるが [5]、この条件下での検知性能を定量的に評価した研究は見当たらない。

Cそこで本研究の目的は、URL 文字列に依存しない HTML 構造特徴量を導入することにより、短縮 URL を含むフィッシングサイトに対しても安定した検知性能が得られるかを明らかにすることである。従来は HTML の取得に伴う遅延が実用上の障壁であったが、ヘッドレスブラウザの高速化によりこの制約は解消されつつある。

D本論文の貢献は、(1) URL に依存しない 27 次元の構造特徴量の設計、(2) 短縮 URL 検体 1,830 件における F 値 0.71 → 0.93 の改善の提示、(3) 特徴量の寄与分析の 3 点である。本論文の構成は以下の通りである。2 章で関連研究を整理し、3 章で提案手法を述べる。4 章で評価実験の設計を、5 章でその結果と考察を示し、6 章でまとめる。

やってはいけない序論Anti-patterns

毎年、必ず出てくるパターン。自分の序論に当てはまっていないか確認する。

パターン症状直し方
作文型「私は〜に興味を持った」「〜を学んだので活かしたいと考えた」個人的動機は削除。社会的・技術的必要性に書き換える
教科書型技術の一般的解説が数ページ続く2 章（関連研究・関連技術）へ移す
落差なし型背景から突然「本研究では〜を提案する」へ飛ぶ「しかし」の段落を挿入する
目的不明型「〜について検討する」「〜を考察する」で終わる「〜を明らかにすることである」と言い切る
開発報告型「〜システムを開発することを目的とする」開発は手段。明らかにしたい問いを書く
言いっぱなし型数値や断定に出典がないすべての事実に [n] を付ける
最終確認 序論を書き終えたら、結論（6 章）と並べて読む。序論の目的と結論が同じことを言っていなければ、どちらかが間違っている。

このトピックのまとめSummary

序論が決まれば、論文の方向は決まる。

  • A 現状：数値と出典で示す
  • B 課題：「しかし」の段落を必ず置く
  • C 目的：1 文で言い切る
  • D 貢献：箇条書きで、動詞で終える
  • 個人的な動機は書かない
  • 技術解説は 2 章へ回す
  • 「開発」を目的にしない
  • 結論と並べて一貫性を確認する
