TOPIC 03

どこから読むか

全部は読まない。しかし全部チェックする

  • 読む順序と、段階を踏んだ読み方を実践できる
  • 精読する論文を絞り込める
  • 読まないと決めた論文も後から引けるように整理できる

操作：← → / Space でページ送り　O キーでスライド一覧

読む順序Reading order

頭から順に読まない。この順に読んで、さらに読む必要があれば精読する。

  1. 論文題目　Title
    対象・手法・主張が凝縮されている
  2. 概要　Abstract
    論文のエッセンス
  3. はじめに　Introduction
    論文の全体像とストーリー
  4. 結論　Conclusion
    成果と、残された課題

ここまでで 10〜15 分。この 4 つで「読む価値があるか」はほぼ判断できる。

なぜこの順なのか 「概要」と「はじめに」を読めば、論文の要旨は分かる。 概要には論文のエッセンスが、はじめにには論文の全体像が書かれているからである （トピック 02）。
成果がはっきりしない論文は読まない 概要と序論を読んでも「何が明らかになったのか」が分からない論文は、 本文を読んでも分からないことが多い。時間は有限である。 ただし「自分の知識不足で分からない」場合と混同しないこと （トピック 01）。

※ 図表を先に眺めてから本文に入る読み方も有効である。ただし数値は条件とセットで読む。

3 段階で読むThree passes

1 本の論文に最初から数時間かけない。段階ごとに「次へ進むか」を判断する。

段階時間読む範囲判断すること
① 選別3〜5 分題目・概要・見出し・図表のキャプション・結論読む価値があるか／どの箱に分類するか
② 通読30〜60 分①＋序論・関連研究・考察。式の導出と実装の詳細は飛ばす主張と根拠の骨格を掴めたか／精読が必要か
③ 精読数時間〜全体。式を追い、実験条件を確認し、自分なら同じ結論に至るかを検証する再現できるか／どこが弱点か
割合の目安 100 本を ①選別 → 20 本を ②通読 → 3〜5 本を ③精読
卒業研究なら、精読するのは最終的に 5〜10 本程度で足りることが多い。
参考 この段階的な読み方は S. Keshav, “How to Read a Paper,” ACM SIGCOMM CCR, 2007 でよく知られている。2 ページの短い文章なので、一度読んでおくとよい。

サーベイ時の読み方Surveying

研究を始めるときは、大量の論文を扱う。読む／読まないの線引きが勝負になる。

  1. 精読する論文は極力減らす
    全部を精読するには時間が足りない。読むと決めた論文だけに時間を使う。
  2. 全部は読まないが、全部チェックする
    読まなくても「あること」は知っておく。必要に応じて後から読めるようにしておく。
  3. 必要な論文はしっかり精読する
    必要に応じて、その論文の参考文献をさらに追う（トピック 15）。
「あることは知っておく」が効いてくる場面 ・卒論の関連研究を書くとき、「この分野にはこういう種類の研究がある」と俯瞰できる
・口頭試問で「○○の研究は知っていますか」と聞かれたときに答えられる
・半年後に「そういえば似た研究があった」と思い出して引ける
そのためには、上手な整理法が必要である。

読む／読まないの判断Screening

5 分の選別で、この観点をチェックする。

精読に進める候補
  • 自分の研究テーマと問題設定が重なる
  • 自分が使おうとしている手法・データセット・評価指標を使っている
  • 概要に具体的な数値が書かれている
  • 査読のある論文誌・国際会議の論文である（トピック 04）
  • 多くの論文から引用されている
  • サーベイ論文である（分野を俯瞰できる）
いったん保留にする
  • 概要を読んでも何が明らかになったか分からない
  • 結果に数値がない（「有効であることを確認した」だけ）
  • 問題設定が自分のテーマから遠い
  • 同じ著者のより新しい論文がある
  • より広く読まれている類似の論文がある

「捨てる」のではなく「保留」にする。記録は残す。

判断してよいこと・いけないこと 「自分に必要か」は判断してよい。「論文として良いか悪いか」を 5 分で判断してはいけない。 必要性と質は別の話である。

精読の進め方Deep reading

精読は「時間をかけて読む」ことではない。検証しながら読むことである。

  1. 用語と記号を先に確定させる
    準備の章・記号表を先に押さえる。定義されていない記号が出てきたら印を付ける
  2. 前提と仮定を書き出す
    何を信頼し、何を攻撃者に許し、何を対象外としているか（トピック 13）
  3. 手法を自分の言葉で図にする
    入力 → 処理 → 出力。描けなければ、まだ理解していない
  4. 実験条件を表にまとめる
    データ・環境・比較対象・指標。書かれていない欄は「不明」と書く
  5. 主張と根拠を線で結ぶ
    考察の各主張について、「その根拠はどの数値か」を対応づける
  6. 自分なら同じ結論を出すかを考える
    出さないなら、どこで意見が分かれるのかを書き留める（トピック 14）
印刷して読む 精読は紙のほうが速い。余白に「?」「!」「→ 要確認」を書き込む。 画面では見落とす限定句が、紙だと目に留まる。

読んだら必ず残すLeave a record

読んだ記憶は 2 週間で消える。記録だけが残る。

最低限これだけは残す（5 行メモ）
  1. 書誌情報（著者・題目・掲載先・年）
  2. この論文は何を明らかにしたか（1 文）
  3. どうやって確かめたか（1 文）
  4. 限界・前提（1 文）
  5. 自分の研究との関係（1 文）

⑤ がいちばん大事である。「自分にとって何なのか」を書いていない記録は、後で使えない。

ワークシートを使う この資料には、上記を含む 論文精読ワークシートを用意してある。 入力内容はブラウザに保存され、Markdown で書き出して自分のノートに貼れる。
やってはいけない記録
  • 概要をコピーして貼るだけ
    → 自分の言葉に直していないと、後で読んでも理解が戻らない
  • PDF を集めるだけで読まない
    → フォルダが増えるだけで、何も残らない

このトピックのまとめSummary

読む技術とは、読まない判断を素早く下す技術でもある。

  • 読む順序は題目 → 概要 → はじめに → 結論
  • 選別（5 分）→ 通読（1 時間）→ 精読（数時間）の 3 段階
  • 段階ごとに「次へ進むか」を判断する
  • 精読する論文は極力減らす
  • 全部は読まないが、全部チェックする
  • 読まないと決めた論文も、記録は残す
  • 精読は「検証しながら読む」こと
  • 読んだら5 行メモ。特に「自分の研究との関係」
今日からできること 気になっている論文を 1 本開いて、5 分だけ使って題目・概要・見出し・結論を読み、 「精読するか／保留か」を決めてみる。これが選別である。
