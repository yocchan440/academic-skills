TOPIC 02

論文の構造（IMRAD）

どこに何が書いてあるかを、読む前から知っておく

  • IMRAD の 4 要素と、実際の章立ての対応を説明できる
  • 各セクションに何が書かれているかを言える
  • 探している情報がどの章にあるかを即座に判断できる

操作：← → / Space でページ送り　O キーでスライド一覧

IMRAD とはIntroduction / Method / Results and Discussion

科学論文の標準的な文章構成形式。ほとんどすべての論文がこの構成になっている。

IIntroduction ／ 序論
なぜこの研究が必要なのか。何が分かっていないのか。この研究は何を明らかにするのか。
MMethod ／ 手法・材料
何を、どのような手順・条件・環境で行ったのか。
RResults ／ 結果
何が得られたのか。事実としての観測値・測定値。
DDiscussion ／ 考察
その結果は何を意味するのか。何が言えて、何は言えないのか。
読者にとっての意味 型が決まっているということは、探している情報の在り処が最初から分かっているということである。 「実験条件を知りたい」なら Method を、「何が新しいのか知りたい」なら Introduction を開けばよい。 頭から順に読む必要がない。
情報系はほぼこの形式 分野によって細部は異なるが、情報系・情報セキュリティ分野の論文はほぼ IMRAD である。 読者もこの構成を前提に読む。IMRAD でない論文は読みにくく、読まれない。

※ A を Analysis（分析）と捉える考え方もある。

実際の章立てTypical sections

和文誌・英文誌のどちらを読むときも、この対応を覚えておけば迷わない。

IMRAD和文英語
—論文題目Title
全体概要、あらまし、内容梗概Abstract
Iはじめに、序論Introduction
I従来研究、関連研究Related Works
M準備、関連技術Preliminaries / Background
M提案方式、提案手法Method / Proposal
M実験、調査、実装Experiment / Implementation
R結果Results
D評価、考察、検討Discussion / Evaluation
D結論、まとめ、おわりにConclusion
—（謝辞）(Acknowledgement)
—参考文献References
—（付録）(Appendix)
章立てには揺れがある
  • 関連研究が最後にある（国際会議に多い）
  • 「準備」の章で前提知識・記法をまとめる
  • 結果と考察が1 章にまとまっている
  • Threat Model が独立した節になる（トピック 13）
  • Limitations / Ethics が独立した節になる
章の名前ではなく役割で見る 名前が違っても、果たしている役割は IMRAD のどれかに必ず当てはまる。 目次を見たら、まず各章を I / M / R / D に割り振ってみる。

各セクションに何が書かれているかWhat each section contains

この表が、この資料の中心である。読む前に、探すものを決める。

セクション書かれていること読むと分かること
題目研究対象・手法・貢献を凝縮した一文読むべき論文かどうかの一次判断
概要背景・目的・手法・結果・示唆（各 1〜2 文）論文全体のエッセンス
序論現状 → 課題（Gap）→ 目的 → 貢献 → 論文構成論文の全体像とストーリー、何が新しいか
関連研究先行研究の分類・各研究の限界・本研究の位置づけ分野の見取り図、この研究の立ち位置
提案手法設計方針・全体構成・各要素・動作例・前提再現するための情報、仮定していること
実験目的・対象・データ・環境・条件・比較対象・指標結果をどこまで信じてよいかの根拠
結果観測された数値・図表（事実のみ）実際に何が起きたか
考察結果の解釈・なぜそうなったか・限界著者の主張と、その根拠の強さ
結論問題・発見・示唆・限界・今後の課題の総括研究の成果、残されている課題
参考文献引用した文献の一覧次に読むべき論文、分野の基礎文献

セクションごとに「何を探すか」What to look for

漫然と読まない。各章で拾うべきものを決めてから開く。

I序論・関連研究で探すもの
  • 「しかし〜は明らかになっていない」の1 文
  • 「本研究の目的は〜である」の1 文
  • 貢献の箇条書き
  • 自分の研究と重なる先行研究の番号
M提案手法・実験で探すもの
  • 前提・仮定（何を信頼し、何を攻撃者に許すか）
  • 入力と出力は何か
  • データセットの出典・件数・取得時期
  • 比較対象と、その実装の出所
  • 評価指標の定義
R結果で探すもの
  • 主張を支えている核心の数値（たいてい 1〜2 個）
  • その数値がどの条件で得られたか
  • 不利な結果が載っているか
D考察・結論で探すもの
  • 結果 → 解釈のつながりの根拠
  • Limitations（限界）の節
  • 今後の課題（＝著者が認めた未解決点）
  • 序論の目的と結論が一致しているか

同じことが 3 回書かれているThree levels of detail

論文は、同じ主張を詳しさを変えて 3 回書く。この性質が、速く読むための鍵になる。

① 概要（数百字）

背景・目的・手法・結果・示唆を各 1〜2 文で。

→ 読むかどうかを決めるための情報

② 序論＋結論（数ページ）

ストーリーと全体像。何が問題で、何をして、何が分かったか。

→ 研究の要旨を理解するための情報

③ 本文（十数ページ）

手法の詳細、実験条件、すべての結果、考察の根拠。

→ 検証・再現するための情報

だから、こう読む 「概要」と「はじめに」を読めば、論文の要旨は分かる。 概要には論文のエッセンスが、はじめにには論文の全体像が書かれている。 ①②で「自分に必要ない」と判断できたら、③には進まない。
ただし ①②だけで引用してはいけない。引用するなら、その主張を支えている本文と数値まで確認する。

セクションどうしの対応を見るConsistency across sections

良い論文では、この 4 つが一直線に繋がっている。ずれていたら、そこが弱点である。

  1. 序論の目的
    本研究の目的は、短縮 URL を含む検体でも検知性能が維持できるかを明らかにすることである
  2. 実験の設計
    短縮 URL を含む 1,830 件を部分集合として評価した
  3. 結果・考察
    その部分集合で F 値は 0.71 から 0.93 へ向上した
  4. 結論
    URL に依存しない特徴量の併用が有効であることを示した
よくあるずれ
  • 序論で掲げた目的が、実験で検証されていない
  • 結論が、序論の目的と別のことを言っている
  • 概要の数値と、本文の数値が一致しない
  • 考察で、実験していない条件まで一般化している
5 分でできる検査 序論の目的文と結論の 1 文目だけを抜き出して並べて読む。 同じことを言っていなければ、その論文の主張は揺れている。

このトピックのまとめSummary

構造を知っていることが、そのまま読む速さになる。

  • 情報系の論文はほぼ IMRAD である
  • 章の名前ではなく、果たしている役割で I/M/R/D に割り振る
  • 各セクションに何が書かれているかを覚えておく
  • 開く前に何を探すかを決める
  • 同じ主張が概要・序論／結論・本文の 3 段階で書かれている
  • 概要と序論で要旨は掴める。引用するなら本文まで
  • 目的 → 実験 → 結果 → 結論の一貫性を確認する
  • ずれているところが、その論文の弱点である
練習 手元にある論文を 1 本開いて、目次だけを見て各章を I / M / R / D に分類してみる。 3 分でできる。これができれば、どこを読めばよいかが分かる。
