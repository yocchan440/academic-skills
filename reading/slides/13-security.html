セキュリティ分野の論文を読む

「安全である」は、必ず条件つきの主張である

  • 脅威モデルを読み取り、主張の範囲を確定できる
  • 安全性の根拠の種類を見分けられる
  • 攻撃論文・防御論文・測定研究を読み分けられる

操作：← → / Space でページ送り　O キーでスライド一覧

この分野に特有の読み方What makes security different

情報セキュリティの論文には、他分野にない前提がある。そこを外すと読めない。

1「安全」は絶対ではない
どんな攻撃者に対して安全なのかが必ず条件として付く。無条件に安全な方式は存在しない。
2相手がいる
攻撃者は論文を読んで対策を回避してくる。「現在検知できる」は「将来も検知できる」を意味しない。
3時間で陳腐化する
攻撃も環境も変わる。数年前の測定結果は、現在の姿ではない。
4運用の制約がある
検知率が高くても、誤検知が多ければ実運用では使えない。率ではなく件数で考える。
5倫理的な配慮が要る
実環境での攻撃実験、人を対象とする調査、脆弱性の公表。どう配慮したかが論文に書かれる。
読むときの第一問 「この論文は、どんな攻撃者を想定しているのか」 — これに答えられなければ、まだ論文を読めていない。

脅威モデルを読むThreat model

この分野でいちばん重要な節。ここを読まずに結果だけ読んではいけない。

読み取る項目問い書かれていないと
攻撃者の目的何を達成しようとしているのか（窃取・改ざん・妨害・なりすまし）何を守れているのか不明
攻撃者の能力何ができるのか（通信の盗聴・改ざん・端末の制御・計算資源）安全性の主張範囲が不明
攻撃者の知識何を知っているのか（手法の詳細・鍵・学習データ）適応的攻撃への耐性が不明
信頼できる主体誰を信頼するのか（OS・サーバ・認証局・利用者）前提が崩れる条件が不明
対象外の攻撃何を扱わないと明言しているか読者が過大に評価してしまう
脅威モデルが書かれていない論文 「あらゆる攻撃に強い」という意味ではない。 「どんな攻撃を想定しているか、読者には分からない」という意味である。 その論文の安全性の主張は、評価できないと記録する（トピック 01）。

脅威モデルの実例Example

論文からこの 5 項目を抜き出して、自分の言葉で書き直す。

3.2　脅威モデル

　目的本研究では、利用者の認証情報を窃取することを目的とする攻撃者を想定する。能力攻撃者は任意のドメインを取得し、正規サイトを模倣した Web ページを公開できる。また、URL 短縮サービスを自由に利用できるものとする。知識攻撃者は、提案手法が用いる特徴量の詳細を把握していないものとする。信頼利用者の端末および提案システムの実行環境は信頼できるものとする。対象外端末へのマルウェア感染、および DNS の改ざんを伴う攻撃は本研究の対象外である。

ここから分かること ・守れるのはフィッシングによる認証情報窃取だけ
・端末がマルウェアに感染していたら無力（対象外と明言）
・攻撃者が特徴量を知ったら破られる可能性がある
研究の種はここにある 「攻撃者が特徴量を知っている場合はどうなるか」＝適応的攻撃の研究。
脅威モデルの仮定を 1 つ外すと、それだけで新しい研究テーマになる。

安全性の根拠は何かEvidence of security

「安全である」と書いてあったら、何をもってそう言っているかを確認する。

根拠の種類どう主張するか読者が注意すること
形式的な安全性証明仮定（計算量的仮定など）のもとで、攻撃の成功確率が無視できるほど小さいことを証明する仮定が現実に成り立つか。証明はモデル内の話である
形式手法による検証プロトコルをモデル化し、ツールで性質を検証するモデル化の際に何を捨象したか
経験的評価実データ・実環境で検知率などを測るデータセットの偏り、未知の攻撃への一般化
既知攻撃への耐性知られている攻撃を試して防げることを示す未知の攻撃は対象外。「破られていない」だけ
ヒューリスティック「〜だから安全と考えられる」と論じる根拠が弱い。語尾を確認する
「攻撃されなかった」は「安全」ではない 既知の攻撃を防げたことは、その攻撃に対して有効だったという意味しかない。 「安全であることが証明された」と読み替えてはいけない（推理の禁止）。

論文の種類で読み方を変えるAttack / Defense / Measurement

セキュリティ分野の論文は、大きく 3 種類に分けられる。

攻撃論文

主張：「この条件下で、この攻撃が成立する」

読むところ：

  • 攻撃の前提条件（どこまで現実的か）
  • 成功率と、その測り方
  • 対象とした実装・バージョン
  • 開示と対策の状況
防御論文

主張：「この脅威モデルの攻撃を防げる」

読むところ：

  • 脅威モデル
  • 検知率と誤検知率の両方
  • オーバーヘッド（速度・資源）
  • 回避可能性の議論があるか
測定・調査研究

主張：「実世界はこうなっている」

読むところ：

  • いつ測ったか
  • どこを測ったか（母集団）
  • 測定手法の妥当性
  • 母集団の代表性
攻撃論文と防御論文は対になっている ある防御手法の論文を読んだら、それを破った攻撃論文が後から出ていないかを確認する。 被引用をたどれば見つかる（トピック 15）。

倫理と開示の記述を読むEthics and disclosure

この分野の論文には、研究倫理への配慮が書かれる。ここも読む。

論文に書かれる配慮
  • 責任ある開示（Responsible / Coordinated Disclosure）
    発見した脆弱性を、公表前に開発者へ連絡したか
  • 倫理審査（IRB / Ethics Review）
    人を対象とする調査の承認を得たか
  • 実験の封じ込め
    実環境に影響を与えない形で実験したか
  • データの匿名化
    収集した通信・ログから個人情報を除いたか
読者が学ぶこと 自分が研究する側になったとき、同じ配慮が求められる。 他人のシステムへの無断アクセスは、研究目的でも 不正アクセス禁止法違反になる。 論文の倫理の節は、その分野で何が許され、何が許されないかの実例集である。
再現しようとする前に 攻撃論文を読んで手法を試したくなったら、必ず自分の管理下の環境で行う。 実施前に指導教員に相談する。

この分野特有の用語Jargon

頻出する用語。知っていれば、読む速度が上がる。

用語の日本語訳は 1 つに決めておく adversary を「敵」「攻撃者」「攻撃主体」と訳し分けると、自分の論文で表記ゆれになる。 読みながら対訳表を作る。

このトピックのまとめSummary

セキュリティ論文の主張は、すべて条件つきである。

  • 脅威モデルを最初に読む。書かれていなければ「評価できない」
  • 攻撃者の目的・能力・知識・信頼・対象外の 5 項目を抜き出す
  • 「安全」の根拠の種類を見分ける
  • 既知攻撃を防げた ≠ 安全
  • 攻撃／防御／測定で読むところが違う
  • 防御論文は誤検知率と回避可能性を見る
  • 測定研究はいつ・どこを測ったか
  • 倫理と開示の記述も読む
この章を読み終えたときに言えること 「この論文は、〔どんな攻撃者〕に対して、〔どんな条件〕のもとで、〔何〕を達成したと主張している」 — これが言えれば、セキュリティ論文は読めている。
